# שלוש הפונקציות ב-Supabase — שם מול slug

🔴 **השם שמופיע בדשבורד אינו הכתובת.** זה עלה לנו שעה: הפונקציה של טים
מוצגת בשם `Tim`, וה-slug שלה — החלק שנמצא בכתובת ושדרכו האתר קורא לה —
הוא `quick-worker`. הקוד קרא ל-`/functions/v1/tim`, קיבל 404 בלי כותרות
CORS, והדפדפן הציג "לא נגיש" במקום "לא נמצא".

⚠️ **והבדיקה שלי אימתה `/functions/v1/tim` ועברה כל הזמן** — כי היא
בדקה את מה שהנחתי, לא את מה שקיים.

| שם בדשבורד | slug (מה שבכתובת) | מה זה |
|---|---|---|
| `Tim` | **`quick-worker`** | תשובות טים. נקראת מהדפדפן. |
| `embed` | **`clever-processor`** | חישוב הווקטורים של מאגר הידע. |
| `aliases-function` | **`hyper-funct…`** ⚠️ | קיצור שמות מתקנים. ה-slug המלא לא נראה בצילום — להשלים כשנצטרך. |

הכתובת המלאה: `https://<project-ref>.supabase.co/functions/v1/<slug>`

## איפה זה חי בקוד

- `apps/web/src/lib/tim.ts` — הקבוע `TIM_FUNCTION` מחזיק את `quick-worker`.
  **הקבוע הוא ה-slug ולא השם**, וזה כתוב שם במפורש כדי שלא "יתוקן".
- `embed` ו-`aliases-function` אינן נקראות מהאתר, ולכן ה-slug שלהן אינו
  בקוד. הוא נדרש רק כשקוראים להן ידנית מבחוץ.

## ⚠️ מה מדביקים בפריסה ידנית (מ-26.09)

**הקוד כבר אינו ב-`supabase/functions/`.** הלוגיקה עברה לשרת
(טים ב-`apps/server/src/tim/`, embed ו-aliases בצנרת — `apps/pipeline/src/enrich/`), והקובץ ל-Supabase **נבנה**:

```sh
npm run build:edge
```

ואז מדביקים ל-Code בדשבורד את הקובץ המתאים, **כולו**:

| פונקציה | הקובץ להדבקה |
|---|---|
| `embed` | `apps/pipeline/dist/edge/embed/index.ts` |
| `aliases-function` | `apps/pipeline/dist/edge/aliases/index.ts` |
| טים (`quick-worker`) | לא ידנית — `deploy-tim.yml` בונה ופורס |

⛔ **לא להדביק את קובץ הלוגיקה עצמו.** הוא הלוגיקה בלבד, בלי
הכניסה של Supabase — הפונקציה תעלה ולא תענה לשום בקשה.

## איך מריצים את `embed` מהדשבורד

בדשבורד לוחצים על השורה **לפי השם** (`embed`) — ה-slug לא נדרש שם.
בפנים: Test → POST → כותרת `x-ingest-secret` עם הערך של `INGEST_SECRET` →
Run. מעבדת עד 25 קטעים בהרצה.

⛔ **הסוד אינו עובר בצ'אט ואינו בקוד.** הוא ב-Secrets בלבד, ונטע מדביקה
אותו ישירות בדשבורד.
