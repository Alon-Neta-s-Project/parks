# מפת המסמכים

מה נמצא איפה, ולמה. **מסמך חדש נכנס לתיקייה — לא לשורש.**

| תיקייה | מה נכנס |
|---|---|
| `architecture/` | איך המערכת בנויה — שליפה, זיכרון, ארכיטקטורת מידע, שמות פונקציות |
| `spec/` | מפרטי נתונים, התאמת סכמה, ניתוח קובצי מקור |
| `product/` | חשיבה מוצרית — מפת דרכים, שלבי המוצר, מסקנות מחקר, בסיס מסחרי |
| `research/` | מחקר של רוני |
| `personas/` | פרסונות |
| `vendors/` | ספקים והשוואות |
| `teams/` | הגדרות צוותים — גבולות אישור, חלוקת תפקידים |
| `howto/` | הוראות הפעלה לפיתוח |

## מה נשאר בשורש, ולמה

`master-brief-v1.md`, `work-plan-v1.md`, `status.md` — מסמכי־על שאינם
שייכים לאף קטגוריה.

⚠️ **`open-decisions.md` ו-`open-items-claude-code.md` נשארים בשורש
בכוונה, עד שיפוצלו.** כל אחד מהם הוא שני דברים מעורבבים: החלטות שנסגרו
ופריטים שעוד פתוחים. פריט פתוח שקבור במסמך ארוך הוא בדיוק מה שהמעבר
ל-Issues נועד למנוע (הכרעת נטע, 14.09).

הפיצול: מה שנסגר → מסמך ארכיון כאן · מה שפתוח → Issue משלו. אושר על
ידי נטע ב-22.09, ממתין לביצוע. **עד אז אל תעבירו אותם לתיקייה — זה
ייראה כאילו הם סודרו.**
